# Lists and Taxonomy: code/API parity and alignment

PaperDotNet source: `96df412f040f53cc14711aaba35880e24817e084`. Evidence comes from current handlers, services, schemas, triggers, validators and tests. This is source comparison plus PaperGo testing; the .NET application was not executed.

PaperGo covers the listed core stories with one accepted deletion policy. A matching story means the corresponding capability exists; it does not imply identical URLs, payload names, error statuses or authorization models. Publishing, declarative validation, frozen schemas and typed edge policies remain PaperGo features.

LST-17 is an accepted difference: the user requires deleting a folder with its contents. PaperGo exposes explicit recursive deletion through REST and folder-tree deletion through WebDAV; PaperDotNet rejects populated folder deletion. Ordinary REST deletion still covers the .NET empty-folder rule. This story needs no further alignment work.

Folder metadata now supports content-type fields, terms and keywords, live reader visibility, indexed collection/Smart Folder queries, shared-schema validation, type changes, bulk edits and recycle recovery. Required/default item fields do not apply to folders.
